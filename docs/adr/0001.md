# ADR 0001: Monorepo com pnpm workspaces

* **Status:** aceita
* **Data:** 03/10/2026

## Contexto

O sistema tem API, site, worker, contratos compartilhados e tokens de design. Hoje `server/` e `client/` vivem no mesmo repositório, mas sem ferramenta que os ligue: a URL da API e os papéis estão duplicados nos dois lados.

## Decisão

Um repositório com `apps/api`, `apps/web`, `apps/e2e`, `packages/contracts` e `packages/design-tokens`, gerenciado por pnpm workspaces. Scripts na raiz (`pnpm dev`, `pnpm test`, `pnpm build`) orquestram tudo.

## Consequências

Mudança de contrato e de tela entram no mesmo PR; o CI roda só o que foi afetado por filtros de caminho. Custo: pipeline um pouco mais elaborada.

## Alternativas consideradas

Repositórios separados (descartado: versões cruzadas e PRs coordenados); npm workspaces (descartado: pnpm é mais rápido e mais rigoroso com dependências fantasmas).
